# Theme Editor

Open **View → Theme → Open Theme Editor…** in TextMate, or run `tm-theme-editor` from the command line. `Applications/ThemeEditor` builds `ThemeEditor.app`, an AppKit helper app embedded in TextMate's app bundle. It runs as a separate process and uses the same installed bundle catalogue, default settings, and editor components as the containing TextMate build. Resizing the window expands or contracts the preview; the theme list and controls retain their chosen widths. Drag the dividers to adjust those widths. Each pane has a minimum width so its controls remain usable; if the window becomes too small for your chosen widths, they shrink safely while the preview continues to fill the remaining space.

## Editing

The left pane groups enabled, visible themes from TextMate's bundle catalogue under **Light**, **Dark**, and **Unspecified**, with names sorted within each section. Section headings scroll with the list instead of staying pinned at the top. Select a theme, or use the **+** button to create one. Right-click a theme for **Duplicate** and **Delete**; these actions apply to the theme you clicked. Delete asks for confirmation, discards any unsaved changes to that theme, and uses TextMate’s bundle deletion behavior: local theme files move to Trash, while installed themes receive a local deletion override. Deleting an unsaved theme discards its draft. If the last theme is deleted, a new unsaved theme opens. **Command-click** a theme to edit its name directly in the left pane. Press Return or click elsewhere to finish editing, or press Escape to cancel the rename and restore the previous name. **Save** persists the new name. New themes are marked “unsaved” until saved.

The middle pane edits **Appearance** and the selected style rule. The three side-by-side Appearance buttons select **Light**, **Dark**, or **Unspecified**, with exactly one selected at a time. Appearance uses the same `semanticClass` metadata as TextMate’s theme menu (`theme.light.…` or `theme.dark.…`). **Unspecified** makes the theme available for either appearance. Changing Appearance moves the draft into its new section immediately; **Save** persists the classification. Existing themes without that metadata remain unspecified, new themes start as Light, and duplicates retain their source’s classification. The category is independent of the background color. Global rules have an empty scope selector. Syntax rules use TextMate scope selectors, such as `comment`, `string`, or `keyword.control`. Rule order and settings that are not exposed by the controls are preserved. Use **Add rule** above the scope selector to enter the new rule’s name in a dialog. Canceling leaves the draft unchanged. Existing rule names are displayed in the style-rule selector; the middle pane edits their scope and appearance. **Remove rule** asks for confirmation and names the selected rule; **Cancel** leaves the draft unchanged.

Each color uses one compact row, with a clickable swatch on the left and its hex field on the right. Colors accept `#RRGGBB` or `#RRGGBBAA`; click the swatch to open the system color panel. The controls and native preview honor the theme’s `colorSpaceName`: `sRGB` when declared, otherwise Apple Generic RGB, matching TextMate. Color-picker selections are converted back into that same space before storing their hex values; existing themes are not retagged or recolored. A blank field removes that override and lets the theme engine resolve its fallback. **Gutter colors** is collapsed by default. Expand it to edit the line-number and editor-margin colors. An unset gutter color shows its inherited preview color in the swatch, so the color picker starts with that color and opacity; these controls always edit the theme's global `gutterSettings`.

**Font settings** is collapsed by default. Expand it to edit the selected rule’s font name, size, and style, or open the native font picker. Fonts accept PostScript names (for example `Menlo-Regular`) and sizes from 4 to 200 points. **Choose Font…** opens the native font panel for the selected rule. Font styles accept TextMate's `plain`, `bold`, `italic`, `underline`, and `strikethrough` keywords, separated by spaces. Font overrides are stored in the theme; scoped/project font settings still participate in TextMate's normal rendering rules.

The right pane is an `OakDocumentView`, including its real `OakTextView`, gutter, and status bar. The preview always shows line numbers so gutter colors can be inspected, without changing TextMate’s line-number preference. Use **Sample language** above the preview to choose JavaScript, TypeScript, TypeScript / React, Python, Swift, Rust, Go, C, C++, C#, Java, Ruby, PHP, SQL, Bash, HTML, CSS, JSON, or Markdown. Each sample has over 50 lines covering the language’s comments, documentation, strings and escapes, numbers, declarations, control flow, and other syntax. TypeScript / React includes typed props, hooks, event handlers, JSX tags and attributes, fragments, comments, and embedded expressions. HTML includes embedded CSS and JavaScript; Markdown includes emphasis, links, lists, tables, and fenced code. The available scopes and styles depend on the language grammar and theme.

Syntax highlighting uses the corresponding installed TextMate language bundle. If it is missing, a message above the preview explains which bundle to install and the sample remains selectable as plain text. Reopen Theme Editor after installing a bundle. The last sample language is remembered.

**Command-click** an element in the preview to select its most-specific matching theme rule in the middle pane. The clicked syntax scope is shown beneath the rule selector. Matching uses TextMate’s own scope-selector ranking; later rules win when specificity ties. When no syntax-specific rule matches, the global style is selected. Theme rules can combine, so less-specific rules may still supply other properties. Command-click inspection leaves the caret, sample text, and theme draft unchanged. Correct any invalid highlighted setting before inspecting another rule.

Samples are editable: select text, fold code, or type more examples to inspect their rendering. **Invisibles** reveals whitespace. Switching samples retains your sample edits for the session and keeps your theme draft, colors, and fonts. **Reset Sample** restores the selected sample’s bundled text. Sample edits do not change the theme, execute the code, or save a source file.

## Saving and reverting

Use **File → Download Theme…** or right-click a theme and choose **Download Theme…** to export it as a standalone `.tmTheme` XML property list. Choose the filename and location in the save dialog. The download includes current valid unsaved edits, preserves the theme's UUID and metadata, and does not save changes to the installed theme or clear its unsaved state. The right-click action exports the clicked theme.

**Save** and **Revert** stay fixed at the bottom of the middle pane and are disabled when there are no unsaved changes. They enable when the theme changes and disable again after saving, reverting, or restoring the original values. The editing controls scroll above that footer when space is limited. **Save** or **Cmd+S** persists the draft using TextMate's bundle item save API. The current theme and style rule stay selected, including when renaming or changing appearance moves the theme within the grouped list. Existing themes retain their UUID and parent bundle; managed or bundled themes receive a local delta override. New and duplicated themes get new UUIDs in a local **Theme Editor** bundle. TextMate's bundle watcher detects these files and refreshes its theme menu.

Drafts have private preview UUIDs and uncached styles, so editing them does not modify installed theme objects. Switching themes, creating another theme, closing the window, or quitting offers **Save**, **Cancel**, and **Discard**. **Revert** uses the same prompt and restores the last loaded or saved version. Correct invalid highlighted settings before saving or switching rules.

The editor checks source files and the merged bundle catalogue before saving. If another editor has changed the theme, it retains the draft and refuses to overwrite the newer version. Reopen the utility to load external changes. The theme list is loaded at launch; reopen the utility after installing additional bundles.

The utility uses `oak::application_t::support()` for TextMate's user support directory and the containing app's resources. It does not install its own shell command automatically. Add `TextMate.app/Contents/MacOS` to `PATH` or symlink `tm-theme-editor` into an existing command directory. Symlink invocation resolves the original executable to find the containing app.

## Development

Build through `make debug` so the Swift library and application resources are present. The `ThemeEditor` CMake target can be built independently for focused compilation, but the embedded executable in the completed app bundle is the supported launch location. TextMate embeds the signed `ThemeEditor.app` in `Contents/Helpers` and its `tm-theme-editor` launcher in `Contents/MacOS` before signing the outer app. The preview opts out of language servers and Copilot.
